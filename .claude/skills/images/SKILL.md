# Images and S3

- Public images (events, articles, scope home pages under `public/scopes/`): store the S3 key in the DB; call `publicImageUrlFromKey(key)` from `~/core/media/images` (modules: from `~/core` or `~/core/ui`) to build a direct browser URL using `VITE_S3_BASE_URL`. Thumbnails are derived with `deriveThumbnailKey(key)`.
- Article featured images: uploaded by `ArticleForm` (`ImageUploader`, path `ARTICLE_IMAGE_PATH` = `public/articles`, cropped 1:1) and stored as the key in `articles.featured_image`. `articlesService` accepts only `public/articles/…` keys, rejecting other prefixes, `..` and URLs (`isArticleImageKey`). Shown through `publicImageUrlFromKey` (cards, hero, article page, og:image/JSON-LD). Notes have no image.
- Profile pictures are split: the full-size image (`private/profile-pictures/`) is stored in `users.profilePicture` and must be presigned server-side via `resolvePrivateImageUrl(key)` from `~/core/media/secure-urls`; the thumbnail (`public/profile-pictures/`) is stored separately in `users.profilePictureSmall` and served as a direct public URL via `publicImageUrlFromKey`.
- `VITE_S3_BASE_URL` (e.g. `http://localhost:4566/data` locally with Floci, `https://<bucket>.s3.<region>.amazonaws.com` in prod) is the base URL for all public S3 objects. It is a Vite env var read via `import.meta.env.VITE_S3_BASE_URL`, not through `src/env.ts` (the one exception to the `src/env.ts` rule).
- Uploads (`src/routes/api/images/index.ts`, `authorizeUpload` in `src/core/media/upload-access.ts`): core's prefixes are profile pictures (any user) and `public/scopes/`, `public/articles/`, `public/page-blocks/` (a managing role on some scope). A module declares its own in the manifest: `uploads: [{ prefix: "public/events/", minRole: "representative" }, { prefix: "private/events/", minRole: "admin" }]` (must be `public/<id>/…` or `private/<id>/…`; checked by `moduleUploadRulesOf`). Only active modules' prefixes are accepted, and the uploader needs `minRole` on the scope of the admin page (`ImageUploader` sends the URL's `[scope]` segment as `x-upload-scope`, so a module uploader must sit on an `/admin/[scope]/…` page). Events: event images and products under `public/events/` (products in `public/events/products`), photo galleries under `private/events/<id>/photos`; deals: logos under `public/deals/logos`. Store the key and check it against the prefix in the service.
- Key validation and presign rules are in CLAUDE.md Security § S3 key handling.
